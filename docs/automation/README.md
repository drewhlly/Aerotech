# Automation and API validation release candidate — 31 October 2026

Current production baseline: `86779f1236eb2d68e004a1f4a806652e07aba636`. This candidate is not deployed or merged. The full consolidated handoff is not complete.

## Audit and changes

| Area | Finding | Change |
| --- | --- | --- |
| API input validation | 34 unhandled HTTP 500 responses across 23 route/method combinations in 415 baseline probes | Validate JSON objects and handle parsing failures before accessing fields; wrong multipart uploads return 400 |
| Recruitment CSV import | A valid Full Name/Email-only CSV threw ExcelJS column-zero errors for missing optional Phone/Position columns | Read optional columns only when present; preserve tenant-scoped duplicate handling |
| Confirmation | Null payloads crashed; recording approval did not change probation status | Typed validation, recent rated review, due-date status transition, delayed application of future decisions and replay-safe notices |
| Employee onboarding | Existing HR tasks had no employee onboarding page | Tenant-scoped checklist, document status, current agreement and explicit acknowledgement |
| Agreements | Migration 037 removed the three company agreement settings fields | Additive migration 042; old snapshots retained; new version numbers avoid historical acknowledgements; HR supplies new text |
| HR lifecycle records | Notification creation attempted two inserts using the same notification ID | Save HR notices directly; assign other record types and their notifications atomically |
| Retried HR assignments | Retries could create repeated records | Stable client delivery key and server tenant-scoped idempotency; legacy identical requests deduplicate within one minute |
| Learning | Repeated completion changed the original completion timestamp | Preserve first completion/acknowledgement and notify HR once; completion remains explicitly employee-reported |
| Checklist completion | HR could create manual tasks but had no completion control | HR-only manual completion; credential tasks complete through document vetting instead |
| Reminders | Renewed documents, completed learning/goals and resolved confirmations could stay in the active inbox | Check current source-record state; retain historical notices |
| Anniversaries and deadlines | Work anniversaries and several due reminders were missing | Idempotent in-app work-anniversary and overdue goal/learning/onboarding notices |
| Monthly scheduler | A fresh on-request report could be regenerated by the month-end job and rearm a read notice | Per-tenant lock and post-period freshness check; isolate failed tenants |
| Scheduled exits | The scheduler did not explicitly revoke sessions and could mark unrelated exit rows complete | Tenant-scoped exit transaction, payroll deactivation and session revocation; employee records retained |
| Form accessibility | Wrapped selects included option text in their label, breaking stable Employee selectors | Explicit label/control associations for lifecycle and confirmation forms |

## Deployment blocker and exact migration

Neon returned `branches limit exceeded` when preparing the isolated migration. No temporary migration branch was created and no production migration was applied. A read-only production schema inspection confirmed that `company_workflow_settings` currently has only employer_id, probation_days, updated_at and credential_types; deploying this candidate without migration 042 would break agreement-dependent queries.

Migration file: `database/042_restore_onboarding_agreements.sql`.

SHA-256: `eb2a937eb385aef9561c6bdba4e09bb71653b8631d0df7a3520266cedc5cfa8c`.

The exact transaction with its migration-ledger entry is in `docs/automation/migration-042-review.sql`. It adds three settings columns and two indexes; historical acknowledgements and business records remain. Old agreement text is not silently republished. Initial version numbers skip archived/acknowledged versions. Local migration tests verify preservation and rerun safety.

Proposed slot to free: older preview database `preview/codex/consolidated-handoff-checkpoint`, branch `br-withered-tooth-b8k7fvvy`, project `polished-cloud-66634472`. Production is branch `br-empty-base-b84a9xdp` and must not be deleted. Deleting the named preview removes its preview data.

Neon's delete and complete-migration tools explicitly require user approval. After approval: delete only the named older preview; prepare the exact reviewed migration; verify the isolated branch and ledger; apply it only if those checks pass; merge the tested candidate; deploy and verify production. Do not merge this candidate before its schema is present.

## Still outstanding from the broader handoff

The ordered applicant identity/CV/general-and-job assessment journey, configurable 85% screening and review controls, live identity/phone provider setup, full leave accrual/carryover/holiday/workweek policies and remaining module-wide acceptance checks are not completed by this candidate. No feature is claimed live solely because the code builds. Workflow dates currently follow the existing Africa/Lagos calendar; company-specific timezone policies remain future work. New agreements require organisation-approved text from HR, not generated legal claims.

## Manual QA checklist after approval and deployment

- Verify each role remains in its own portal; employees see Onboarding and never Recruitment/payroll processing.
- Publish an HR-approved agreement, acknowledge it as the employee, change the text and verify a new acknowledgement is required while old evidence stays intact.
- Upload credentials and verify only HR approval completes the associated task; complete a manual HR task and see it on the employee checklist.
- Assign learning, complete it as the employee, retry and verify the first timestamp/history remains.
- Confirm an eligible probation employee against recorded performance; check scheduled decisions and do not infer termination from a negative review.
- Renew an expiring document and complete overdue work; check that active notices resolve and history remains.
- Retry monthly scheduling; verify reports and read notices are not duplicated/rearmed and due exits affect only the correct tenant.
- Repeat public/protected production smoke checks and scan deployment-scoped runtime logs.
